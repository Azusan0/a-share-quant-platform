# A股盯盘与推荐引擎重构开发文档

版本：v7.6（2026-08-05）  
适用目录：`a_share_alert_template`

## 1. 目标与非目标

### 1.1 目标

把当前“动态板块监控 + 日线信号提醒”升级为可解释、可回评、可执行的推荐引擎：

```text
全市场数据
  → 可交易过滤
  → 板块强度与持续性
  → 先锋/中军/补涨角色
  → 多周期技术结构
  → 5分钟状态机
  → 风险收益与可成交性
  → 推荐/观察/拒绝
  → 推荐生命周期与回评
```

### 1.2 非目标

- 不让LLM决定技术状态或直接预测涨跌。
- 不把封死涨停当成可执行买入推荐。
- 在影子验证完成前，不扩大Hermes实盘消息推送。
- 不复制GPL项目源码；只重新实现其架构思想。

## 2. 当前架构问题

1. 正式推荐链主要使用日线策略，5分钟状态机当前只展示和落库。
2. 日线策略使用“当日累计成交量 / 历史均量”，早盘会漏信号，午后容易追涨。
3. 动态池成员分数奖励当日涨幅、日内高位和成交额，偏向已经上涨的股票。
4. `amount_ma_period`、`entry_min_amount_ratio` 配置没有进入有效触发计算。
5. 量能缺失时部分策略把未知当作通过；正式推荐缺少数据完整性门槛。
6. 封死涨停在部分路径被视为最强入场，但用户实际无法按推荐价成交。
7. 推荐没有结构化入场区间、失效价、最高追价和风险收益比。
8. 市场环境只调整分数门槛，没有统一控制推荐数量、状态门槛和仓位。
9. 推荐后缺少“触发、成交、失效、取消、止盈止损、回评”的生命周期。

## 4. 推荐数据契约

推荐引擎输出的每个标的至少包含：

```json
{
  "recommendation_status": "recommend|watch|reject",
  "recommendation_type": "first_ignition|confirmation|pullback|second_ignition|anchor|overheated",
  "state": "setup|ignition|confirmation|pullback|second_ignition|overheated|failed|dormant",
  "role": "leader|core|catch_up|anchor",
  "sector_score": 0,
  "candidate_score": 0,
  "recommendation_score": 0,
  "entry_low": 0,
  "entry_high": 0,
  "max_chase_price": 0,
  "invalid_price": 0,
  "target_price": 0,
  "risk_reward": 0,
  "data_quality": "complete|partial|stale|missing",
  "blockers": [],
  "reasons": [],
  "expires_at": ""
}
```

状态规则：

- `ignition`：可以进入早期推荐，但必须有量能和VWAP支持。
- `confirmation`：可推荐，要求突破持续至少一根5分钟K。
- `pullback`：可低吸，要求回踩缩量且未跌破失效价。
- `second_ignition`：优先级最高，要求回踩后再次放量。
- `setup`：只能观察，不能推荐。
- `overheated`、`failed`、`dormant`：拒绝推荐。

## 5. 评分与门控

### 5.1 推荐总分

推荐总分不是简单相加涨幅：

```text
推荐分 = 0.30 × 板块分
       + 0.25 × 个股结构分
       + 0.25 × 分时状态分
       + 0.10 × 相对强弱分
       + 0.10 × 可交易性分
       - 风险惩罚
```

### 5.2 必须通过的硬门槛

- 行情不是过期或跨交易日污染。
- 量能数据存在且单位一致；缺失只能降级为观察。
- 非ST、非退市整理、非停牌。
- 非封死涨停；封板只保留为`anchor`。
- 分时状态必须属于可执行集合。
- 市场极弱时禁止普通突破推荐。
- 风险收益比不低于配置阈值，默认2.0。

### 5.3 角色规则

- `leader`：板块内强度最高，负责确认方向，不默认推荐。
- `core`：流动性和趋势最稳定，优先作为执行标的。
- `catch_up`：涨幅较低但处于蓄势/回踩/二次启动，重点寻找早期机会。
- `anchor`：ETF或封板龙头，只作方向锚，不给可执行买入价。

## 6. 分阶段实施

### P0：基础推荐引擎（已完成）

1. 新增推荐引擎并接入影子扫描。

4. 参数版本化和滚动样本外验证。

## 7. 验收标准

- 早盘同一只股票的量比不因累计时间短而系统性偏低。
- 5分钟`setup`、`dormant`、`overheated`不能输出`recommend`。
- 封死涨停只能输出`anchor`或`watch`，不能输出可执行推荐。
- 每条推荐都有入场区间、失效价、目标价、风险收益比和过期时间。
- 数据源缺失时不生成可执行推荐。
- 同一根K线重复执行不会增加状态持续根数或重复推荐。
- 影子运行不触发Hermes入场消息。
- 现有动态池、离场提醒、日志回评和看板不回归。
